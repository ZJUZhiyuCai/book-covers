[English](README.en.md) · [查看第二辑](https://zjuzhiyucai.github.io/book-covers/?shelf=volume-2#collection)

2026-10-16。使用 **Book Covers Skill 1.4.0**，新增十部作品。每部交付无字 PNG、中英文各一张字体排版 PNG，以及完整提示词 TXT。这里记录实际制作过程，包含失败与保留意见。

**本轮结论：文字与文件交付稳定；插画的简约程度仍需审阅。** 这些是同一 Agent 在同一环境中指导完成的十例，不是无人干预的成功率测试，也不能代表所有题材或宿主。

## 怎么测

- 固定 Skill 和排版器版本；基线提交为 `e177a920978348d9a529f887de7c72b0f51024f2`。本轮没有修改 Skill 或排版核心。关键文件哈希见 [verification.json](verification.json)。
- 五部中文文学、五部外国文学。中文书名长 2–9 字，英文标题长 7–29 个字符；包含单行、两行、三行、中文竖排、毛笔字、英文斜体，以及 García Márquez 的重音符号和较长中文作者名。
- 由 Agent 逐书编写构图和排版方案，再用内置生图工具生成。实际提示词保留在 [prompts](../../../prompts/)，首轮方案保留在 [briefs.json](briefs.json)。
- 每张无字图单独目视检查；中英文成品分别检查大图与 180 px 宽缩略图。作者名在这么小的缩略图中较细，完整阅读仍宜打开大图。
- 实际调用已安装 Skill 的独立排版器，随后将相同输入导出到另一个目录，比较全部文件的 SHA-256，并与画廊构建结果核对。

## 已暴露的局限

1. **“少画”不是稳定的硬约束。** 模型容易把旧建筑、木器和土地补成丰富的纹理，或添加合理但未要求的道具。以后应先限定有意义的大形体，必要时做一次明确删减，而不是只加更多否定词。
2. **坐标是方向，不是遮罩。** 《月亮与六便士》等画面没有准确停在指定百分比。实际排版尚有净空，但不能把提示词中的坐标当成像素保证。
3. **构图开始趋同。** 这轮多次使用院落、门窗、桌椅；既有模型的惯性，也有本轮 Agent 写 brief 的偏向。应把“不同作品是否真的有不同构图”列为整组审阅项，而非把同一空室换色就算新设计。
4. **自动检查只解决一部分问题。** 字形、界限和哈希通过，不代表文学关联鲜明或已达到出版级设计。需要用户或独立设计者继续判断。
5. **覆盖范围有限。** 未做不同图像模型、多随机种子、独立 Agent、Windows/Linux 字体栅格化或印刷测试。本次数据不支持泛化成功率。

## 接入画廊时的修正

画廊原来固定显示“10 部作品”，宣传图也假设每个文学分类只有五本。现改为动态总数、第二辑筛选和分辑展示，避免新增书目挤出画布。

原页面把所有生图编辑都说明为“底部留白修正”。现按每部作品读取真实编辑提示词、原因和独立配方。首次集成测试曾因旧数据的字符串原因与新双语原因对象不兼容而失败；保留旧格式兼容后增加回归检查，19 项测试通过。这个集成问题不计作 Skill 排版失败。

浏览器检查通过：第二辑筛选显示 10 部，全部显示 20 部，中英文切换保留筛选；原图切换和《围城》的真实返工记录正常。390 × 844 视口下，作品列表与长英文题页面均无横向溢出。下载链接与复制内容已核对，未把浏览器下载或剪贴板往返计为实测。

## 复跑方法

依赖准备完成后，在仓库根目录使用当前 Skill 的排版器。下例只复跑既有原图上的文字，不重新调用生图：

```sh
node skills/book-covers/runtime/compose.mjs \
  --spec docs/stability/vol-02/specs/unknown-woman.json \
  --out output/stability-replay/unknown-woman \
  --receipt output/stability-replay/unknown-woman-audit.json
```

使用已安装版本时，把命令中的 `skills/book-covers/runtime/compose.mjs` 换为对应 Skill 的路径。输出目录应为空，以保留默认的覆盖保护。可对 `specs/` 中十个文件分别运行，并在另一个空目录重复，再比较 SHA-256。首次依赖与字体准备见 [runtime.md](../../../skills/book-covers/references/runtime.md)。
